# 项目文档命名与语言规范

本文件是 `agent-engineering-master` 生成项目级文档时的命名、语言与历史归档排序的权威规范（SSoT）。

## 1. 核心规则

Agent Engineering 内部 Skill、协议 ID、Registry Key、Schema Key 可以使用英文。

**生成到用户业务项目中的项目级文档，默认必须同时满足：**

1. 文件名使用中文；
2. 文档正文使用简体中文（`zh-CN`）；
3. 标题、章节名、说明文字、表头、清单项、面向用户的状态描述默认使用中文；
4. 技术专有名词、代码标识符、API 名、类名、字段名、协议名、库名可以保留英文；
5. 代码块、配置键、Schema Key 不要求翻译，避免破坏可执行性；
6. 用户明确指定其他语言时，以用户要求为准。

禁止仅把文件名改成中文、正文仍大量使用英文模板字段。

## 2. 项目文件映射

| 内部 ID | 项目实例文件 |
|---|---|
| project.yaml | 项目状态.yaml |
| boundary-canvas.md | 边界画布.md |
| decision-ledger.md | 决策记录.md |
| current-session.md | 当前会话.md |
| project-intake.md | 项目调研.md |
| architecture.md | 架构设计.md |
| change-impact.md | 影响分析.md |
| verification-report.md | 验证报告.md |

`history/` 作为内部归档目录名保持英文，目录中的归档文档主题必须使用中文。

## 3. 历史归档时间命名规范

所有 `history/` 文件必须使用**固定宽度、可按字符串直接排序的时间前缀**：

```text
YYYYMMDD-HHmmss-<task-id>-<中文主题>.md
```

示例：

```text
20260831-153312-task-042-需求澄清.md
20260831-161005-task-043-架构冻结.md
20260901-091500-task-044-功能验证.md
```

如果没有 `task-id`，使用：

```text
YYYYMMDD-HHmmss-<中文主题>.md
```

### 3.1 为什么必须这样命名

`YYYYMMDD-HHmmss` 从年到秒均为固定宽度且补零，因此按普通文件名字典序升序排列时，天然等于真实时间升序。

禁止以下混用：

```text
2026-8-9-9-5-2-xxx.md
8-31-2026-xxx.md
31-08-2026-xxx.md
task-042-20260831-153312-xxx.md
20260831-3-5-9-xxx.md
```

这些格式会导致字符串排序与时间排序不一致。

### 3.2 时区规则

项目必须使用一个稳定的 `project_timezone`。

优先级：

1. 用户明确指定的项目时区；
2. 项目现有配置中的明确时区；
3. 首次初始化时的运行环境本地时区，并写入 `项目状态.yaml`。

后续归档必须始终使用同一个 `project_timezone`，禁止同一项目内混用 UTC、系统本地时区和其他时区。

### 3.3 同秒冲突

同一秒内生成多个归档文件时，在时间后添加两位递增序号：

```text
20260831-153312-01-task-042-需求澄清.md
20260831-153312-02-task-043-边界确认.md
```

### 3.4 排序语义

规范默认定义：

```text
文件名升序 = 时间从旧到新
```

不要通过反转时间数字来实现“最新优先”。如果某个 UI 需要最新记录显示在最前面，应在展示层对列表做降序排序，而不是破坏文件命名的时间可读性。

## 4. 语言规范

项目实例 Markdown 必须默认使用简体中文，包括：

- 文档标题；
- 一级至多级章节标题；
- 字段展示名；
- Markdown 表格表头；
- 说明文字；
- 检查清单；
- 面向人的状态含义；
- 结论、建议、风险、原因、验证说明。

允许保留英文的内容：

- `TaskRequest`、`AgentState`、`ToolInput` 等代码/契约标识符；
- `Pending`、`PASS` 等机器协议值，但应附中文含义；
- `LangGraph`、`Redis`、`PostgreSQL`、`HITL`、`RBAC` 等技术名词；
- 路径、命令、代码、配置键和 Schema Key。

## 5. 禁止事项

禁止：

- 将项目状态写入 `skills/templates/`；
- 使用英文文件名生成用户项目文档；
- 生成中文文件名但正文仍为英文模板；
- 多项目共享同一个 `.agent-engineering` 状态目录；
- `history/` 中混用不同日期格式；
- 日期或时间不补零；
- 同一项目混用多个时区；
- 把 task-id 放到时间前面作为历史文件首排序键。

## 6. 允许事项

允许：

- Skill 内部使用英文 ID；
- Registry 使用英文 Key；
- Runtime 使用英文协议；
- Schema/配置使用稳定的英文 Key；
- 技术专有名词保留英文；
- 用户明确要求时生成其他语言的项目文档。
